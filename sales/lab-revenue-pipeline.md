## Stage definitions

- **Cold** — first outreach sent, no response yet
- **Responded** — first response received, not yet qualified
- **Qualified** — confirmed they have a relevant need and interest
- **Scoping** — scope conversation underway, sprint offering selected
- **Proposal** — SOW + pricing sent, awaiting decision
- **Close** — verbal commitment, paperwork in motion
- **Won** — SOW signed, work scheduled or started
- **Lost** — declined, lost to competitor, or went silent after proposal

## Channels

- **U** — University with VC fund
- **V** — Early-stage medtech VC
- **M** — Large medtech corporate
- **D-NI** — Defense tech, non-ITAR
- **D-I** — Defense tech, ITAR (US team only)
- **N** — Network referral (specify source in notes)

## ID format

Use sequential 3-digit IDs prefixed with channel code: `LR-V001`, `LR-U001`, etc. Sequence is global, not per-channel. First opportunity = `LR-001` regardless of channel; channel goes in its own column.

## Update protocol

After every meaningful interaction (outreach sent, reply received, call scheduled, call completed, proposal sent, contract signed):

1. Find the row by ID (or add a new row if first contact)
2. Update stage if it moved
3. Update value if scope clarified
4. Update next action and last touch date
5. Add brief note if substance worth recording

No CRM, no fancy tooling. This file is the system of record.

## End-of-day review (during 3-week sprint)

10-minute review at end of each day:

- What moved today?
- What's stuck and why?
- Who needs follow-up tomorrow?
- Are pipeline counts on track for week-end gates (see `lab-revenue-3-week-sprint.md`)?
